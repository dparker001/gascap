# ChatGPT Review Packet — Phase 1 P1-A (activation instrumentation + three UX fixes)

**Status: READY FOR INDEPENDENT REVIEW — P1-A.** Not merged, not deployed. Base `2a9c837` (main).
Authority: owner authorization for P1-A only (docs/PHASE1_ACTIVATION_PLAN.md, merged `2a9c837`).

## 1. Objective
Instrument the activation funnel, show time-bounded Phase 1 activation metrics in the admin
baseline panel, and fix three user-facing defects: the dead `/?log=1` deep link, the
no-vehicle fill-up logger dead end, and the blocking first-login mode selector.

## 2. Repository State
Branch `feat/phase1-activation-p1a` from `origin/main` `2a9c837`. No schema, migration, experiment,
P1-B or P1-C work. `public/sw.js` (regenerated by `npm run build`) was restored, not committed.

## 3. What I Found
- `/?log=1` (first-fill-up nudge, email + push) has no reader anywhere; it landed on the home page.
- `ManualFillupLogger` with zero vehicles showed only "Cancel".
- The mode selector was a blocking modal with no escape and no event.
- `vehicle_saved`, `fillup_logged` (personal + gig) and password-register `signup_completed`
  hard-coded `originPlatform: 'unknown'`. OTP signup already records a real platform; Google signup
  (`lib/auth.ts` callback, no request in scope) still cannot determine one.
- Existing events already cover Signup / Vehicle Added / First & Second fill-up; no duplicate events were added.

## 4. What I Changed
1. **Events:** only `mode_selected` {mode: personal|gig|rental|fleet} and `mode_skipped` (no metadata) added to the client
   allowlist (`app/api/analytics/event/route.ts`), authenticated-only, strict schema.
2. **Platform:** `lib/originPlatform.ts` derives ios/android from the GasCapiOS/GasCapAndroid UA markers, `web` only for
   a positively identified standalone browser (desktop UA, iOS Safari/Chrome/Firefox/Edge, Android Chrome/Firefox/Samsung
   without the `wv` flag), otherwise `unknown`. Passed to `vehicle_saved`, personal and gig `fillup_logged`, password
   `signup_completed` via optional params (default `unknown`).
3. **Activation metrics:** `lib/activationMetrics.ts` (pure), `loadFuelActions()` (read-only), route returns an added
   `activation` key (Phase 0.5 fields untouched; activation failure -> `activation:null`), new panel section.
4. **`/?log=1`:** `components/LogIntentHandler.tsx` + `lib/logIntent.ts`. Authenticated only; strips the param with
   `history.replaceState` (other params/hash preserved); one-shot intent with 15 s TTL; `ToolsPanel` selects Log,
   `ManualFillupLogger` consumes once and opens (visible instance only); native switches to the Tools tab. No redirects.
5. **No-vehicle logger:** "Add a vehicle" button (EN + ES) dispatches the existing `gascap:focus-vehicles` event
   (opens the normal VehiclePicker); after `vehicle-saved` it refetches and returns the user to the open logger.
6. **Mode selector:** "Skip for now" (web + native). Skip writes nothing to the profile, leaves `userMode` null, emits
   `mode_skipped` once, and is remembered per user in localStorage (`hooks/useModeSelectorSkip.ts`) so it does not
   return on every load. Selecting a mode is unchanged and emits `mode_selected` once, after the save succeeds.
7. Help page + AI chat APP FEATURES updated; EN/ES translations added.

## 5. Architectural Decisions
- Activation is computed from **records** (Fillup, GigFillup), not events, so history before instrumentation counts and a
  missed analytics write cannot hide a fuel action.
- Local date: the `User` model has no timezone, so the documented baseline fallback (America/New_York) applies; a per-user
  `timeZone` is honoured if one is ever supplied.
- Timing uses record `createdAt` (logged-at), per the approved plan, so back-dating cannot create activation.
- "Distinct local date" is the local date of that logged-at instant.

## 6. Security Impact
No auth change. Client allowlist gained two authenticated-only events with strict enums (no PII, no free text).
Admin route unchanged in authorization (`requireAdmin`, fail closed). UA-derived platform is a label only and is never
used for authorization.

## 7. Data / Database Impact

## 8. User / Business Impact

## 11. Known Risks / Remaining Questions
1. **Existing test changed:** `signupTrialAnalytics` G2 asserted that vehicle_saved/fillup_logged *always* use the literal
   `originPlatform: 'unknown'`. That rule is exactly what P1-A changes; G2 now accepts the request-derived form and still pins
   rental_setup_completed / trial_expired to `'unknown'`. Please confirm this is acceptable.
2. **Platform coverage is deliberately partial.** An iOS WKWebView without the marker stays `unknown`. Google signup, CSV
   vehicle import, rental fill-ups and `trial_started` still write `unknown` (out of the approved list / no request in scope).
3. **E85 / null-grade fill-ups qualify** (any gallon-based `Fillup`); the owner wording is "gasoline/diesel". Confirm or I will exclude `fuelGrade = 'e85'`.
4. **Skip is per-browser.** Clearing storage or a new device re-shows the selector once.
5. The `gascap:focus-vehicles` handler lives in `SavedVehicles`; if that component is not mounted when the button is tapped
   the picker will not open (same limitation as the existing setup checklist). I did not verify in a browser.
6. Gig `fillup_logged` source is `gig_fillup_create`; rental fill-ups are counted from `Fillup.rentalSessionId`, not from rental events.
